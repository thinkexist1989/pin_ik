# 阶段 B：截止时间、取消与工作区复用

日期：2026-11-06。实现基线为阶段 A 提交 `c085321`。阶段 B 实现及本地解正确性验证已通过；尚未达到整机 1 ms 零超期验收。

## 实现范围

| 方案要求 | 实现 |
| --- | --- |
| 共用绝对截止时间 | 从公开 `CartToJnt()` 入口记录 `steady_clock` 时间；两个工作线程与底层求解器接收同一 deadline。独立调用底层求解器时，仍按其 `maxtime` 计算一次 deadline。 |
| 完善停止检查 | 领取任务后、Newton FK/雅可比/分解前后、随机重启前，以及每次 NLopt optimize/回调/逐维差分处检查。非正剩余时间不传给 NLopt。 |
| 修复取消回调 | SumSq、L2、DualQuat 与 Joint 约束统一初始化误差和梯度；停止或找到有效解后退出差分，不读取无效输出。仅 NLopt 所属线程调用 `force_stop()`。 |
| 异常处理 | 只处理预期的 `nlopt::forced_stop` 与 `nlopt::roundoff_limited`；非预期停止和内存/参数错误继续传播，经常驻线程完成屏障交还调用方。 |
| 工作区复用 | 每工作线程的 seed/output、Newton 配置/雅可比/增量/临时向量/COD 对象、NLopt 参数/扰动/约束输入/人工边界/目标关节缓冲区按模型预分配。 |
| 结果内存 | Speed 最多两个候选槽按有效结果回收复用；其他模式保留动态候选数、评分与 `getSolutions()` 语义。 |
| 运动学复用 | 增加写入已有配置缓冲区的转换重载；只更新目标 frame。串联链复用 FK 计算过的关节状态来求雅可比；带旁支模型保留末端专用雅可比路径。 |
| 实例独立性 | DualQuat 目标从全局状态移入求解器实例，随实例分配和回收。 |

没有修改梯度的 `2h` 分母、随机数生成策略、五种模式的选择规则或公开求解签名。类布局变化仍要求重编译客户端。候选比较和分解本身不可被抢占，截止时间不是整个同步调用的硬上界。

Pinocchio 3.9.0 的本地 `algorithm/jacobian.hpp` 明确提供在 FK 之后调用的无 `q` 参数 `computeJointJacobians(model, data)`；这里先 FK 判断是否已收敛，只有未收敛时才计算雅可比，保持 seed 已满足目标时的短路径。分支模型的全模型雅可比会计算无关关节，因此通过构造时的祖先链检查选择路径。

NLopt 非正 `maxtime` 会禁用时间停止条件，且 `maxtime` 本身不保证严格执行上界，参见 [NLopt 官方停止条件](https://nlopt.readthedocs.io/en/latest/NLopt_Reference/#stopping-criteria)。异常分类参见 [NLopt C++ 参考](https://nlopt.readthedocs.io/en/latest/NLopt_C-plus-plus_Reference/#exceptions)；本机实际使用的头文件及库版本随环境证据记录。

## 验证方法

1. Release CTest 保留原有功能、100,000 次混合调用、受控工作线程顺序和生命周期验证，新增 `solver_deadlines` 定向测试。
2. 新测试覆盖正常回调、回调入口取消、第一次差分时取消、对应截止时间路径、基准评估成功后不再差分、优化前过期、回调内 `bad_alloc` 传播与恢复。四种 NLopt 内部模式均执行非零 seed 的多圈连续关节求解，并检查 FK 和限位。
3. 调度前使本轮 deadline 到达，断言两个工作线程都不启动 FK 或优化。正常超时后检查 `-3` 与 seed 输出。使用测试专用钩子记录 deadline 和取消到两个工作线程完成的延迟。
4. 串联链和添加 12 个旁支的模型各取 100 组配置，对比两种雅可比路径，并以 `log6(T(q)^-1 T(q+h))/h` 验证 LOCAL 坐标约定；连续关节包含多圈角度。
5. 使用阶段 A 相同的独立解析 FK 基准，在独立进程中对比阶段 B、阶段 A 与真正的 KDL TRAC-IK。KDL 源自指定本地仓库迁移前提交 `4335714`，不是该仓库现有 Pinocchio 版本。
6. 地址/泄漏/未定义行为与线程检查采用独立构建。分配诊断用 glibc preload 计数，不与正式性能数据混用。

## 正确性与检测结果

环境为 i7-1260P、16 个逻辑 CPU、Linux `6.8.1-1061-realtime`，GCC 11.4 Release，Pinocchio 3.9.0、KDL 1.5.1、运行时 NLopt 2.7.0。进程使用 `SCHED_OTHER`，未配置专用核或实时优先级。阶段 A、优化前基线及 KDL 库的 SHA-256 与阶段 A 报告留存值一致。

宽预算正确性组使用 20 ms、`eps=1e-6`，包含两个六轴模型、五种模式、目标跳变、近限位、6R 近奇异及不可达目标；连续关节包含多圈 seed。各后端输入逐项一致。每个成功解通过独立解析 FK 验证，位置/姿态共同门槛为 `5e-6 m/rad`，限位门槛为 `1e-8`。

| 版本 | 可达成功 | 不可达正确失败 | 最大位置残差 m | 最大姿态残差 rad |
| --- | ---: | ---: | ---: | ---: |
| 阶段 B | 3000/3000 | 400/400 | 9.964e-7 | 9.445e-7 |
| 阶段 A | 3000/3000 | 400/400 | 9.990e-7 | 9.906e-7 |
| KDL TRAC-IK | 3000/3000 | 400/400 | 1.603e-6 | 1.392e-6 |

6R 允许不同有效关节分支，不要求逐位一致；3P+3R 同时核对局部唯一解。失败返回不混入成功解统计。

| 检查 | 结果 |
| --- | --- |
| Release CTest | 4/4 通过：原有功能、100,000 次混合调用、阶段 B 定向测试、随机 IK 示例 |
| NLopt 取消/异常 | SumSq、L2、DualQuat、Joint 全部通过；额外 80 次非零 seed 实际求解通过 FK 与限位检查 |
| LOCAL 雅可比数值检查 | 串联/12 旁支模型共 200 组配置，最大列向量误差 `1.363e-8`，小于 `2e-7` 门槛 |

检测配置沿用阶段 A：TSan 仅对诊断进程使用 `setarch -R`；ASan 显式匹配预编译 Pinocchio 的 Eigen malloc 对齐约定。检测耗时不作为正式性能结果。

## 分配与运动学诊断

glibc preload 计数覆盖每次求解区间的 `malloc/calloc/realloc`，包括对应第三方分配。每组预热 100 次后执行 1000 次，输入相同，所有调用成功。以下是每次调用的平均次数。

| 路径 | seed 已满足目标：A → B | 近目标 seed：A → B |
| --- | ---: | ---: |
| Newton | 1 → 0 | 16 → 6 |
| NLopt | 9 → 3 | 539.745 → 5.341 |
| 双线程入口 | 12.934 → 2.658 | 40.514 → 8.996 |

NLopt 数量变化同时受取消后停止差分、优化迭代/重启和缓冲复用影响，不能全部归因于预分配。Newton 的分解/求解内部仍有分配；计数也不覆盖所有自定义或 aligned allocator。这里确认分配下降，不承诺整调用零分配。

独立运动学诊断每路径 20,000 次的观测均值（μs）：

| 模型 | FK + computeFrameJacobian | computeJointJacobians(q) + getFrameJacobian | FK + computeJointJacobians(data) + getFrameJacobian |
| --- | ---: | ---: | ---: |
| 串联链 | 0.330 | 0.268 | 0.283 |
| 12 旁支 | 0.549 | 0.616 | 0.594 |

串联链采用第三条 FK 复用路径：它允许先判断 seed 是否已收敛，避免为已满足目标的 seed 计算雅可比。旁支模型保留第一条路径。三条路径均做数值一致性验证，选择不改变误差和雅可比的 LOCAL 坐标约定。

测试专用钩子记录了 1000 次不可达请求（550 μs 预算）：截止时间到两个工作线程完成的延迟均值 `7.23 μs`、最大 `163.78 μs`；取消通知前至完成的最大值 `163.58 μs`。这包含调度与收尾，且有插桩成本，只是诊断观测，不是严格上界。

## 1 kHz 与背景负载边界

周期测试仍使用相同 6R 目标、550 μs 预算，按绝对时刻每 1 ms 释放，共 10,000 次，不跳过迟到任务。它不包含实际控制器的采集、通信和控制律。

| 环境/版本 | 成功数 | 调用均值 μs | 调用最大 μs | 调用超 550 μs | 调用超 1 ms | 预定释放至返回超 1 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 常规 / B | 9997 | 155.84 | 1052.95 | 7 | 1 | 1 |
| 常规 / A | 9999 | 230.24 | 877.65 | 4 | 0 | 1 |
| 常规 / 修改前 | 9988 | 311.99 | 4555.42 | 272 | 7 | 15 |
| 常规 / KDL | 9991 | 311.76 | 3553.53 | 303 | 3 | 10 |
| 六个 CPU 负载进程 / B | 9999 | 52.14 | 2288.17 | 3 | 1 | 3 |
| 六个 CPU 负载进程 / A | 10000 | 57.40 | 620.68 | 3 | 0 | 3 |

后台负载采用六个持续整数运算的 Python 子进程，继承 CPU 亲和性和 `SCHED_OTHER`，测试结束全部回收。该条件下另执行每组 20,000 次紧密调用：6R 平滑目标 B/A 均全部成功，均值 `18.19/21.84 μs`、最大 `375.24/2541.87 μs`；3P+3R 平滑目标双方各超时一次，所有成功解仍有效。负载下周期均值反而更低，不能据此推断负载提升实时可靠性；本次没有隔离电源管理和调度因素。

绝对 deadline 会让预算耗尽的晚启动线程直接退出，不能用扩大超时或放松精度掩盖失败。因此短预算下的成功率单列：本轮周期组 B 的成功率略低于 A，且仍有超期。**本次目标“阶段 B 修改并通过解正确性测试”已达成；性能尾部尚无全面改善证据，百万周期整机零超期验收尚未完成。**

# 阶段 C：随机状态、评分锁与数值梯度

日期：2026-11-06。基线为阶段 B 提交 `599c04f`。本次提交保存阶段 C 实现与已完成的正确性验证；分项性能验收尚未完成。

## 实现与比较版本

| 版本 | 相对前一版本的独立改动 |
| --- | --- |
| B | 已提交的阶段 B 基线，保留其原始库与匹配头文件 |
| C1 | 替换进程级 `rand()`；每实例有四条独立 `mt19937_64` 序列，由各工作线程独占使用；构造阶段播种，热路径不访问熵源 |
| C2 | 每工作线程独立配置/Pinocchio Data/雅可比/SVD 评分工作区；评分在结果锁外执行，锁内去重、提交候选与分数 |
| C | 修正共用 NLopt 前向差分的分母 `2h → h`，并将步长从 `FLT_EPSILON` 改为 `sqrt(double epsilon)` |

`setRandomSeed(uint64_t)` 只允许空闲时调用，固定种子可复现各条序列；调度与截止时间仍会影响搜索次数和最终获胜解。限位重建会复制底层随机状态，不静默重置序列。单实例串行调用约束、返回数量、五种模式、候选排序与 `getSolutions()` 语义不变，客户端需重新编译。

评分仍使用 `LOCAL_WORLD_ALIGNED` 雅可比及原有可操作度/限位惩罚公式。`Speed`/`Distance` 使用原有关节距离评分。取消、同步完成屏障和统一 deadline 沿用 B。

解析梯度在方案中属于后续候选，本次采用经数值验证的有限差分修正，没有引入 `Jlog6` 解析导数、修改随机重启范围、放宽容差或改变默认双算法策略。

## 梯度问题与回归

先在 B 的实际测试库上运行同一梯度探针。四种模式的梯度与中心差分参考的投影比均为 `0.5`，验证了分母错误。修正分母但保持原步长时，`Joint` 模式的第一个非零 seed 回归用例无法在 100 ms 内达到 `1e-7` 容差；改用双精度扰动步长后，该用例及完整回归通过。未提高预算或放宽验收容差。

测试共 600 组配置，覆盖 SumSq、L2、DualQuat 和 Joint 约束，包含多圈角度以及 bounds 内屏蔽的残差分量。数值参考为 `h=1e-6` 的中心差分。误差定义为 `||g-g_ref||/(1+||g_ref||)`，门槛 `5e-5`。

| 模式 | B 最大误差 | C 最大误差 | C 平均梯度比例 |
| --- | ---: | ---: | ---: |
| SumSq | 0.418942 | 4.488e-8 | 1 |
| L2 | 0.286790 | 2.991e-8 | 1 |
| DualQuat | 0.259856 | 3.271e-7 | 1 |
| Joint 约束 | 0.422373 | 5.104e-8 | 1 |

这些数值检查避开分段边界和旋转对数分支点；不能把不光滑点的有限差分结果当作解析可微性证明。

## 验证与性能

已完成的检查如下，原始日志和汇总保存在 [证据目录](validation/stage_c/)。

| 检查 | 结果 |
| --- | --- |
| Release CTest | 6/6 通过，包含 100,000 次工作线程调用、底层求解器、deadline、数值梯度、评分与随机状态回归 |
| TSan | 4/4 通过，覆盖工作线程、deadline、梯度和优化回归，无报告 |
| ASan / LSan / UBSan | 5/5 通过，包含独立求解器，无报告 |
| C / B / KDL 宽预算正确性 | 每个版本均为 3,000/3,000 可达目标成功、400/400 不可达目标正确失败 |

三方比较使用同一基准输入，覆盖两种机器人、五种模式及平滑、跳变、限位、奇异和不可达场景，预算 20 ms。KDL 为迁移前 `4335714` 的 TRAC-IK 实现；B 为 `599c04f`。详细数据见 [正确性汇总](validation/stage_c/correctness-summary.json)。这组宽预算数据用于检查正确性，其中的耗时不作为短预算性能结论。

| 版本 | 最大位置残差 | 最大旋转残差 |
| --- | ---: | ---: |
| C | 9.9894e-7 | 9.5838e-7 |
| B | 9.9909e-7 | 8.8421e-7 |
| KDL | 1.5270e-6 | 1.3447e-6 |

运行环境沿用 A/B：Intel i7-1260P、16 个逻辑 CPU，Linux `6.8.1-1061-realtime`，GCC 11.4、Pinocchio 3.9、NLopt 2.7、KDL 1.5.1；普通 `SCHED_OTHER` 调度，未绑定 CPU。Sanitizer 不是性能计时环境。TSan 使用 `setarch x86_64 -R`；ASan 构建使用 `EIGEN_MALLOC_ALREADY_ALIGNED=1` 匹配本机预编译 Pinocchio 的 Eigen 分配约定。

新增评分锁回归最初使用条件变量定时等待，触发本机旧版 TSan 对 `pthread_cond_clockwait` 的拦截兼容问题；改为普通谓词等待并由 CTest 的 60 秒超时兜底后重跑通过，没有添加告警屏蔽。分母修正但保留旧差分步长的失败记录也保留在证据目录，便于核对最终步长选择。

## 尚待完成的性能验收

已提供 B → C1 → C2 → C 的独立核心补丁和比较工具，复现方式见 [基准说明](../tests/benchmark/README.md#阶段-c-分项比较)。尚未完成以下测量：

- 各阶段在 550 µs 预算下的成功率、候选数量与解质量，以及独立 NLopt 的函数评估次数比较。
- 生产库完整 `CartToJnt` 的均值、P99、P99.9、最大耗时和超过 1 ms 次数；重复轮次以评估调度波动。
- 1 kHz 周期调用及真实控制器上的整机验收。

因此本次提交不能据此认定 C 比 B 更快，或已达到 1 ms 零超期。锁外评分会在去重前执行，重复候选也可能增加评分计算；需要在分项测量中核对其净收益。固定种子也不能消除双线程调度和超时带来的结果差异。

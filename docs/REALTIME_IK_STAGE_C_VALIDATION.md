# 阶段 C：随机状态、评分锁与数值梯度

日期：2026-11-06。基线为阶段 B 提交 `599c04f`，阶段 C 核心实现提交为 `5145db0`。三项实现、正确性检查、独立分项比较和本地周期测量已完成。6R 上独立 NLopt 的短预算成功率提高；完整双线程调用未呈现所有场景下的一致加速，后台负载下仍有超过 1 ms 的调用，整机实时验收未通过。

## 实现与比较版本

| 版本 | 相对前一版本的独立改动 |
| --- | --- |
| B | 已提交的阶段 B 基线，保留其原始库与匹配头文件 |
| C1 | 替换进程级 `rand()`；每实例有四条独立 `mt19937_64` 序列，由各工作线程独占使用；构造阶段播种，热路径不访问熵源 |
| C2 | 每工作线程独立配置/Pinocchio Data/雅可比/SVD 评分工作区；评分在结果锁外执行，锁内去重、提交候选与分数 |
| C | 修正共用 NLopt 前向差分的分母 `2h → h`，并将步长从 `FLT_EPSILON` 改为 `sqrt(double epsilon)` |

`setRandomSeed(uint64_t)` 只允许空闲时调用，固定种子可复现各条序列；调度与截止时间仍会影响搜索次数和最终获胜解。限位重建会复制底层随机状态，不静默重置序列。单实例串行调用约束、返回数量、五种模式、候选排序与 `getSolutions()` 语义不变，客户端需重新编译。

评分仍使用 `LOCAL_WORLD_ALIGNED` 雅可比及原有可操作度/限位惩罚公式。`Speed`/`Distance` 使用原有关节距离评分。取消、同步完成屏障和统一 deadline 沿用 B。

解析梯度在方案中属于后续候选，本次采用经数值验证的有限差分修正，没有引入 `Jlog6` 解析导数、修改随机重启范围、放宽容差或改变默认双算法策略。

## 梯度问题与回归

先在 B 的实际测试库上运行同一梯度探针。四种模式的梯度与中心差分参考的投影比均为 `0.5`，验证了分母错误。修正分母但保持原步长时，`Joint` 模式的第一个非零 seed 回归用例无法在 100 ms 内达到 `1e-7` 容差；改用双精度扰动步长后，该用例及完整回归通过。未提高预算或放宽验收容差。

测试共 600 组配置，覆盖 SumSq、L2、DualQuat 和 Joint 约束，包含多圈角度以及 bounds 内屏蔽的残差分量。数值参考为 `h=1e-6` 的中心差分。误差定义为 `||g-g_ref||/(1+||g_ref||)`，门槛 `5e-5`。

| 模式 | B 最大误差 | C 最大误差 | C 平均梯度比例 |
| --- | ---: | ---: | ---: |
| SumSq | 0.418942 | 4.488e-8 | 1 |
| L2 | 0.286790 | 2.991e-8 | 1 |
| DualQuat | 0.259856 | 3.271e-7 | 1 |
| Joint 约束 | 0.422373 | 5.104e-8 | 1 |

这些数值检查避开分段边界和旋转对数分支点；不能把不光滑点的有限差分结果当作解析可微性证明。

## 独立分项比较

B → C1 → C2 → C 的核心补丁分别保存在证据目录，依次应用后的 `include/`、`src/` 已与当前实现逐文件核对。各版本使用匹配头文件及库。`stage_c_probe` 链接测试支持库，仅用于同条件诊断；正式耗时使用链接生产库的 `ik_benchmark`。所有成功输出检查 FK 和限位。

分项输入来自固定生成器，分别使用近目标 seed 和独立随机 seed；连续关节包含 `8π`。3P+3R 模型用于简单情形，6R 模型与正式基准的几何、限位和工具坐标一致，用于多分支解质量比较。宽预算 20 ms、每组 100 次；6R 短预算 550 µs、每组 500 次，运行两轮，第二轮倒序执行版本。运行前完成所有编译与 Sanitizer 检查。

### 梯度修正

6R 独立 NLopt 的短预算结果如下。每格为第一轮 / 第二轮；成功率与全部调用的耗时分开统计，未通过放宽精度或提高预算换取成功。

| 版本 | 近 seed 成功数 / 500 | 随机 seed 成功数 / 500 | 近 seed 均值 µs | 随机 seed 均值 µs |
| --- | --- | --- | --- | --- |
| B | 448 / 448 | 448 / 448 | 149.8 / 133.6 | 160.1 / 157.0 |
| C1 | 449 / 449 | 449 / 449 | 148.0 / 133.6 | 158.3 / 157.8 |
| C2 | 449 / 449 | 449 / 446 | 134.1 / 139.7 | 158.5 / 169.0 |
| C | 482 / 479 | 496 / 496 | 96.0 / 109.2 | 103.1 / 107.4 |

20 ms 的 6R 独立 NLopt 中，B 两类 seed 分别成功 97/100、98/100，C 为 100/100、100/100。只比较 C2 和 C 都成功的同一批宽预算用例，最后一次 `optimize()` 的平均目标函数评估次数：近 seed `25.38 → 24.08`，随机 seed `30.60 → 30.39`。短预算共同成功用例中，近 seed 两轮均为 `24.04 → 22.34`，随机 seed 分别为 `29.30 → 29.49`、`29.23 → 29.46`。这不是跨随机重启的总迭代数；NLopt 没有直接提供本工具所需的 SLSQP 内部迭代计数。

收益依赖模型。3P+3R 独立 NLopt 的评估次数反而从近 seed `8.04 → 14.98`、随机 seed `9.81 → 16.93`，B/C 均全部成功，均值由 `29.81/37.60 µs` 增至 `41.87/54.42 µs`。因此保留该修正的依据是导数正确性及上述 6R 收敛收益，不能称为所有模型上的梯度加速。

### 随机状态、评分锁与解质量

6R 短预算分项中，四个版本的双线程入口、两类 seed、五种模式在两轮中均为每组 500/500 成功。固定种子只固定各自随机序列，不能消除线程调度和超时导致的搜索差异。

下表合并两轮、两类 seed 和三种 `Manip*` 模式，每行 6,000 对共同成功用例。每项仅比较相邻版本，评分越大越好；差值不超过 `1e-12 + 1e-4*max(abs(a),abs(b))` 视为等效。该阈值只用于统计，不修改 IK 容差。

| 独立改动 | 评分改善 | 等效 | 评分变差 |
| --- | ---: | ---: | ---: |
| B → C1：随机状态 | 391 | 5225 | 384 |
| C1 → C2：锁外评分 | 83 | 5820 | 97 |
| C2 → C：梯度 | 230 | 5632 | 138 |

锁外评分的可控调度回归证明了一个线程评分时，另一个线程仍可提交结果；20 ms 的 `Manip*` 配对中 600 对有 599 对评分等效、1 对改善。但短预算测量没有证明 C2 具有稳定净性能收益：如 `Manip1` 随机 seed 的平均候选数，C1/C2 两轮分别为 `2.008/2.000`、`2.028/1.954`。重复候选在去重前也会计算评分，存在额外工作量；当前保留独立工作区和缩短临界区的实现，不据此宣称更快或每个用例都得到更优解。`Distance` 的逐项配对及所有候选数量、评分均见分项 JSON。

### 分段计时定位

因负载下尾部没有一致改善，另用匹配测试支持库、同样输入和六进程负载执行 B/C 各 10,000 次诊断。记录发布至各工作线程进入求解的时间、线程求解墙钟/CPU 时间、首个线程结束至两线程完成，以及最后完成至调用端取样的时间。插桩有开销，这批数据不混入上面的生产库统计。

诊断中 B/C 分别有 8/3 次调用超过 1 ms，说明超期数量本身也随运行变化。C 最慢样本总耗时 `1462.00 µs`：Newton 发布后 `72.37 µs` 开始，耗费 `31.40 µs` CPU；NLopt 发布后 `1438.15 µs` 才开始，耗费 `1.65 µs` CPU；最后完成到调用端取样为 `20.41 µs`。另外两次 C 超期，晚开始的线程分别等待 `1359.89 µs`、`1253.99 µs`。B 最慢样本也有 `2728.55 µs` 的发布至工作线程开始间隔。

这证明这些诊断样本的主要延迟发生在进入求解前，不能归因于求解计算本身耗时 1 ms。该区间包含通知、锁交接和操作系统调度，不能仅靠此探针细分每种等待原因。即使一个线程已有有效解，调用端仍须等另一个线程确认完成，避免上一周期继续访问下一周期状态；不能为降低测得耗时而跳过完成屏障。

## 验收结论与后续范围

阶段 C 的随机状态隔离、独立评分工作区/锁外评分、数值梯度修正及各自验证已完成。梯度修正改善了本次 6R 独立 NLopt 的短预算收敛，双线程模式成功输出的精度、限位和评分语义保持有效；随机序列变化和短预算搜索会改变具体解，逐项质量变化已记录。

**完整调用尾部没有全面改善，1 ms 零超期目标尚未达到。** 下一步应按阶段 D 在真实控制器上测线程优先级、CPU 亲和性、调度/电源配置及其他任务干扰，继续保留三线程交接的分段计时。本阶段未改变调度策略，未执行百万周期整机验收，不能把本机 10,000 周期结果或平均耗时当作硬实时保证。
